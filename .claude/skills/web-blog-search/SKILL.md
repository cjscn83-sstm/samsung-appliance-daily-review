# Web Blog Search

## 목적

네이버 블로그를 제외한 다양한 출처에서 **지정 일자** D에 게시된 삼성 가전 후기를 수집한다.

## 입력 인자

- `date` (필수): 수집 대상 일자, `YYYY-MM-DD` 형식.
- 인자가 없으면 어제를 기본값으로 사용.

## 절차

1. 카테고리 트리에서 검색 키워드 목록을 가져온다.
   - **네이버 블로그는 광고·체험단·판매글 비중이 매우 높으므로 보조로만 쓰고**, 커뮤니티·전문 소스를 우선한다.
   - 키워드에 **`단점`·`장단점`·`솔직 후기`** 를 섞어 균형 잡힌 실사용 후기를 유도한다. (예: `삼성 무풍 에어컨 후기 단점`)

   **[1순위] 커뮤니티 지정 검색 — `WebSearch` + `allowed_domains`** (가장 솔직한 실단점/댓글 토론):
   ```
   WebSearch(query="삼성 무풍 에어컨 후기 단점",
     allowed_domains=["clien.net","fmkorea.com","dcinside.com","ppomppu.co.kr",
       "mlbpark.donga.com","slrclub.com","dvdprime.com","meeco.kr","r.samsungmembers.com"])
   ```
   - 위 도메인 = 클리앙·에펨코리아·디시인사이드·뽐뿌·MLB파크·SLR클럽·DVDPrime·미코·삼성 멤버스(삼성 커뮤니티). 오디오(버즈)는 `dvdprime`·`meeco` 외 필요 시 헤드폰 커뮤니티 추가.
   - WebSearch는 링크+요약을 주므로 **요약 속 실제 불만/장점 문장을 발췌**로 쓰고 출처는 해당 커뮤니티로 표기.

   **[2순위] 네이버 지정 소스** — `search_kin`(지식iN Q&A), `search_cafearticle`(결과의 `cafeurl`로 삼성스마트폰·폰다방·JN테크리뷰·디벨로이드·닥터헤드폰 등 IT 카페 우선), `search_webkr`(노써치·오늘의집·삼성닷컴 D2C·rentre).

   **[미지원]** YouTube 댓글·스레드/트위터(SNS)·소비자상담센터는 전용 커넥터 미연결로 수집 불가. 차량·게임·맘카페 등 제품과 무관한 카페는 제외.
2. 다음 `mcp__naver-search__*` 도구를 `sort: "date"`(최신순), `display` 크게로 사용한다.
   **WebFetch/fetch는 사용하지 않는다** — 본문은 검색 결과의 `description`(약 200자 스니펫)으로 대체한다.
   - `search_webkr` (일반 웹·티스토리·브런치·커뮤니티 문서)
   - `search_cafearticle` (다음/네이버 카페)
   - `search_kin` (지식iN Q&A 후기)
3. 각 키워드로 검색한 결과에서:
   - URL이 `blog.naver.com`이면 **무조건 제외**
   - **날짜 검증 규칙 (엄격)**: 이 소스들(카페/웹/지식iN/커뮤니티 WebSearch)은 게시일 필드가 없다.
     본문·스니펫에서 **입력 `date`임을 증명하는 근거(작성일 표기 등)가 없으면, 그 항목은 당일 후기로 집계하지 않는다.**
     - 게시일이 검증된 항목만 `02-sentiment.md`의 당일 매트릭스·발췌·메트릭에 포함한다.
     - 게시일 미검증 항목은 (원하면) 별도 **"커뮤니티 참고(비일자)"** 로만 남기고 **당일 카운트에서 제외**한다. 추정으로 당일 처리 금지.
   - **신뢰성 원칙**: 데일리 브리프는 "그날의 후기"라는 계약이 핵심이다. 날짜가 불확실하면 버린다(양보다 신뢰).
   - **이미지형 제휴 고지 검증(선택, 로컬 전용)**: 네이버 블로그 제휴 고지("네이버 쇼핑 커넥트… 수수료 제공")가 **이미지로만** 있어 텍스트로 안 잡히는 경우가 흔하다. 텍스트에 제휴 신호(판매가·원가·할인율, `naver.me`/스마트스토어 링크)가 보이는 **경계 글만** 골라 `mcp__playwright__browser_navigate`로 렌더 → `browser_take_screenshot` → 상단 고지 이미지를 판독해 제휴 여부를 확정한다. 전량 렌더는 비용·속도상 금지(의심글만). 클라우드 무인 환경에선 Playwright 미가용일 수 있음.
4. 각 글에 출처 유형 태그를 부여:
   - `[블로그]` — 티스토리, 브런치, 워드프레스 등 개인 블로그
   - `[카페]` — 다음/네이버 카페
   - `[커뮤니티]` — 디시, 뽐뿌, 클리앙, 보배드림 등
5. 광고성 신호를 평가해 표시한다.
6. 결과를 **`artifacts/{date}/01-web-raw.md`**에 저장한다.

## 산출물 형식

```md
# 웹/카페/커뮤니티 수집 결과 — {date}

## 수집 통계

- 총 수집: N건
- 출처 유형별: 블로그 N1 / 카페 N2 / 커뮤니티 N3
- 광고성 의심: M건

## TV/영상∙음향

### TV (N건)

| 제목 | URL | 도메인 | 출처유형 | 작성일 | 발췌 | 광고성 |
| --- | --- | --- | --- | --- | --- | --- |
| ... | ... | tistory.com | [블로그] | ... | ... | [정상] |

...

## 수집 0건 품목

- ...
```

## 품질 기준

- `blog.naver.com` URL 0건이어야 한다 (자가 점검 필수).
- 게시일 필드가 없는 소스(웹/카페/지식iN)는 최신순 상위만 수집하고 **"게시일 미상(최근 수집)"** 으로 표시한다.
- 카페/커뮤니티 글은 로그인 필요 여부를 표시 ("로그인 필요" 메모).
- 발췌는 검색 결과 `description` 스니펫을 그대로 사용한다 (요약·재구성 금지).

## 애매할 때

- 같은 글이 여러 도메인에 미러링되어 있으면 원본 또는 가장 먼저 발견한 것 하나만 유지.
- 출처 유형 판단이 애매하면 도메인을 우선해 `[블로그]`로 표시.
- 검색 결과가 0건인 키워드는 "수집 0건"으로 남기고 다음으로 진행.
