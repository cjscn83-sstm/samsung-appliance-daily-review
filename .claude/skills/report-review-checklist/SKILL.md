# Report Review Checklist

## 목적

작성자가 만든 초안에서 누락·편향·근거 부족·카테고리 일관성 문제를 잡아 신뢰할 수 있는 최종본이 되도록 한다.

## 절차

1. `artifacts/03-draft.md`, `artifacts/02-sentiment.md`, `.claude/references/samsung-category-tree.md`를 모두 읽는다.
2. 아래 7개 항목을 순서대로 평가한다.
3. 각 항목에 ✅(통과) / ❌(미흡) / ⚠️(주의) 중 하나를 표시하고 한 줄 근거를 적는다.
4. 판정 규칙대로 PASS / REVISE를 결정한다.
5. REVISE인 경우 수정 지시 목록을 작성한다.
6. 결과를 `artifacts/04-review.md`에 저장한다.

## 7개 체크 항목

| # | 항목 | 통과 조건 |
| --- | --- | --- |
| 1 | 어제 날짜만 다루는가 | 헤더와 본문 어디에도 다른 날짜 후기가 섞이지 않음 |
| 2 | 카테고리 누락 없는가 | 카테고리 트리의 모든 세부 품목 섹션이 존재 (수집 0건도 명시) |
| 3 | 인용에 출처 링크가 있는가 | 모든 인용 줄에 URL 또는 출처 마크다운 링크가 포함 |
| 4 | 광고성 비중이 표기되어 있는가 | 한눈에 보기 + 각 카테고리 섹션에 광고성 카운트 표시 |
| 5 | 긍정/부정 균형이 정직한가 | 광고성 위주 인용으로 한쪽 의견이 부풀려지지 않음 |
| 6 | 종합 트렌드에 근거가 있는가 | 종합 트렌드의 주장이 매트릭스 또는 키워드 데이터로 뒷받침됨 |
| 7 | 카테고리 트리와 일치하는가 | 대분류 순서와 세부 품목명이 트리 그대로 (임의 통합·이름 변경 없음) |

## 판정 규칙

- ❌가 **1개 이상** → **REVISE**
- ⚠️만 있고 ❌가 없으면 → **PASS** (단 다음 회차 개선 사항으로 기록)
- 모두 ✅ → **PASS**

## 산출물 형식

```md
# 검토 결과 — {어제 날짜}

## 체크리스트

| # | 항목 | 평가 | 근거 |
| --- | --- | --- | --- |
| 1 | 어제 날짜만 다루는가 | ✅ | 헤더와 본문 모두 2026-05-25 |
| 2 | 카테고리 누락 없는가 | ❌ | 김치냉장고, 정수기 섹션 없음 |
| 3 | 인용에 출처 링크가 있는가 | ⚠️ | TV 부정 인용 1개 URL 누락 |
| 4 | 광고성 비중이 표기되어 있는가 | ✅ | 한눈에 보기에 X% 명시 |
| 5 | 긍정/부정 균형이 정직한가 | ✅ | 광고성 표시된 인용은 부록으로 분리 |
| 6 | 종합 트렌드에 근거가 있는가 | ⚠️ | "AI 기능 호평"의 카운트 근거 약함 |
| 7 | 카테고리 트리와 일치하는가 | ✅ | 트리 순서 일치 |

## 판정

**REVISE** (❌ 1개)

## 수정 지시

1. **카테고리 섹션 추가** (체크 #2)
   - "## 주방가전 > ### 김치냉장고" 섹션을 추가하고 "어제 신규 후기 없음" 표시
   - "## 주방가전 > ### 정수기" 동일

2. **출처 링크 보강** (체크 #3, ⚠️라도 함께 수정 권장)
   - TV 부정 인용 첫 번째 줄에 URL 추가

3. **종합 트렌드 근거 보강** (체크 #6, 다음 회차 가능)
   - "AI 기능 호평" 주장 옆에 매트릭스 수치(예: "긍정 9건 중 5건이 AI 키워드 언급") 추가

## 다음 회차 개선 사항

- ⚠️ 항목들은 다음 회차에서 점검
```

## 품질 기준

- 취향 기반 평가 금지 (체크리스트 항목만 사용).
- 통과 기준을 임의로 낮추지 않는다.
- 수정 지시는 작성자가 바로 고칠 수 있도록 섹션명·문장 단위로 구체적으로.

## 애매할 때

- 광고성 후기 인용이 부적절하다고 판단되면 체크 #5를 ❌로.
- 인용 출처 URL이 1-2개만 누락이면 ⚠️, 5개 이상이면 ❌.
- 카테고리 누락은 항상 ❌ (트리 일관성은 타협하지 않음).
